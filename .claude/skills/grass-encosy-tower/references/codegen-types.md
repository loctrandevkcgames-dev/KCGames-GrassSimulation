## [PolyEnumStruct] (`FW/EncosyTower.Core/PolyEnumStructs/PolyEnumStructs.cs`, namespace `EncosyTower.PolyEnumStructs`)

```csharp
[PolyEnumStruct] struct { bool SortFieldsBySize; bool AutoEquatable; bool WithEnumExtensions; Type Container; }
[EnumCaseValue(object)]  [EnumCaseIgnore]  [PolyEnumFactoryFor(typeof(X))]
```

Rules (generator docs + analyzer `GEN/EncosyTower.Core.Generators/PolyEnumStructs/Analyzers/PolyEnumStructAnalyzer.cs`):
- The enum-struct is a `partial struct`; every nested struct is a case (use `[EnumCaseIgnore]` to exclude one).
  At least one case is required (`SG_POLY_ENUM_STRUCT_0001`). An `Undefined` case (value 0) is added implicitly;
  declaring two `Undefined` cases is an error (`..._0014`).
- Cases are `partial struct` or `readonly partial record struct Name(payload)`; declare shared behavior on
  `partial interface IEnumCase` (members must match name, return type and parameters in every implementing case).
  Generic methods are not supported (`..._0002`, `..._0003`).
- `SG_POLY_ENUM_STRUCT_0017`: a case field's type must have hand-written declarations. A type whose every declaration is
  generated (for example a generated `Async`, `EnumCase` or `<Enum>Extended`) is an error; hand-declared `[WrapRecord]` /
  `[UnionId]` partials are fine (sample case `ItemNotYetAcquired(ItemId Id)`). Sources:
  `PolyEnumStructAnalyzer.cs:131-136, 334-353`, `GEN/EncosyTower.SourceGen.Common/TypeReachabilityExtensions.cs:24, 64`.
- When `IEnumCase` declares members, write the `Undefined` case yourself, as `PlayerDataError.cs` does.

Generated (snapshot `GEN/EncosyTower.SourceGen.Tests/Core/PolyEnumStructs/Snapshots/RecordParameter_Int32...`):
nested `enum EnumCase : byte` (`Undefined = 0`, then cases), `IEnumCase` with `GetEnumCase()` and `To<Type>()`, a
constructor per case, implicit case to enum-struct, explicit enum-struct to case, `GetValueOrThrow(T<Case>)`,
`GetValueOrDefault`, `TryGetValue(out Case)`, `Value`, `HasValue` (`IHasValue`).

Sample (typed error with deferred message composition): `SAMPLES/EncosyTower.Samples.Persistence/Persistences/PlayerDataError.cs`:

```csharp
[PolyEnumFactoryFor(typeof(Error))]          // wrapper exposes a static factory per case: PlayerDataError.ItemAlreadyAcquired(id)
public readonly partial struct PlayerDataError { /* private ctor(in Error), ToString() => _error.ToMessage(prefix) */
    [PolyEnumStruct] readonly partial struct Error {
        partial interface IEnumCase { FixedString512Bytes ToMessage(in FixedString64Bytes prefix); }
        public readonly partial record struct ItemNotYetAcquired(ItemId Id) { public FixedString512Bytes ToMessage(...) { ... } }
    }
}
```

Use for: variant state (CODING-CONVENTIONS 8.5) and typed errors for `Result<TValue,TError>` / `Success<TFailure>`
(8.2). Store inputs, compose text only in a cold `ToMessage`. Note `Result<TValue,TError>` needs `TValue != TError`.

## [WrapRecord] / [WrapType] (`FW/EncosyTower.Core/TypeWraps/TypeWrapAttributes.cs`, namespace `EncosyTower.TypeWraps`)

```csharp
[WrapRecord] struct/class { bool ExcludeConverter; }                      // requires a positional record with exactly ONE parameter
[WrapType(Type type, string memberName = "value")] { bool ExcludeConverter; } // on a non-record struct/class
```

```csharp
[WrapRecord]
public readonly partial record struct LevelId(int Value);   // pattern from SAMPLES/EncosyTower.Samples.Data/Common.cs (HeroId(short Value))
```

Generated for an int wrapper (snapshot `GEN/EncosyTower.SourceGen.Tests/Core/TypeWraps/Snapshots/WrapRecordStruct_GeneratesWrapper...`):
implements `IWrap<int>`, `MaxValue`/`MinValue`, implicit conversions to and from `int`, comparison/arithmetic operators,
`CompareTo`, `Equals`, `Parse`/`TryParse`, `ToString` overloads, and a `TypeConverter` (unless `ExcludeConverter`).
Do not use `[WrapType]` on a record (use `[WrapRecord]`).
Parse/TryParse forward to the wrapped type and return the wrapped primitive, not the wrapper (for `int`: `public static int Parse(string s) => int.Parse(s);`, snapshot lines 56-105). Conversions are implicit both ways and arithmetic/bitwise operators are generated (snapshot lines 133-229): any `int` silently becomes the id, so keep raw ints out of APIs that should take a `LevelId`.

## [EnumExtensions] (`FW/EncosyTower.Core/EnumExtensions/EnumExtensions.cs`, namespace `EncosyTower.EnumExtensions`)

```csharp
[EnumExtensions] public enum FruitType : byte { Apple, Orange }          // on the enum
[EnumExtensionsFor(typeof(DayOfWeek))] public static partial class DayOfWeekExtensions { } // for enums you do not own
```

Generates `<Enum>Extensions` (static partial) and `<Enum>Extended` struct. Members (snapshot
`GEN/EncosyTower.SourceGen.Tests/Core/EnumExtensions/Snapshots/`): `ToStringFast`, `ToDisplayStringFast`, `ToFixedString`,
`AsExtended`, `ToUnderlyingValue`, `TryParse(string|ReadOnlySpan<char>, out T, ignoreCase, allowMatchingMetadataAttribute)`,
`IsDefined`, `IsNameDefined`, `TryFormat`, `FindIndex`, `Values.AsSpan()/AsMemory()/ToNativeArray(allocator)`.
`ToFixedString`, `ToDisplayFixedString` and `Values.ToNativeArray` are generated only when the assembly references
`Unity.Collections` (`EnumExtensionCompilationSpec.cs:16`, `HasReferencedAssembly("Unity.Collections")`;
`EnumExtensionsDeclaration+WriteCode.cs:81, 265`); `GrassSimulation.Gameplay.asmdef` does not reference it today.
Sample: `GEN/Samples/Samples.EnumExtensions/Samples.EnumExtensions.cs`. Replaces `Enum.ToString()`/`Enum.Parse` on hot paths.

## [UnionId] (`FW/EncosyTower.Core/UnionIds/`, namespace `EncosyTower.UnionIds`)

Composite ids made of a kind plus a value; `UnionIdSize` is `Default`, `UShort`, `UInt`, `ULong`, `UInt3`, `ULong2`
(`UnionIdSize.cs`). Verified usage only:

```csharp
[UnionId(Size = UnionIdSize.ULong, KindSettings = UnionIdKindSettings.PreserveOrder)]
[UnionIdKind(typeof(NoneType), 000, nameof(NoneType.None))]
public readonly partial struct ItemId { ... }                     // SAMPLES/EncosyTower.Samples.Persistence/Shared/ItemId.cs
[UnionIdKind(typeof(HeroId), 0, "Hero", signed: true)]            // SAMPLES/EncosyTower.Samples.Data/Common.cs (EntityId)
```

Kind types are `[WrapRecord]` ids or enums (`ItemId` uses the enum `NoneType`, `SAMPLES/.../Shared/NoneType.cs`). Needs hand-written `TryParse_<Kind>` partials in some setups (Data sample). Heavy;
only for a real multi-kind id such as a skins catalog (Later).

## Where it applies in GrassSimulation

`LevelId` as `[WrapRecord]`; level/state enums with `[EnumExtensions]`; save/settle/session errors as
`[PolyEnumStruct]` behind `Result`/`Success`; per-state variants (level phase, tool state) as `[PolyEnumStruct]`.
