# Driving the GrassSimulation Editor

This skill is a thin, project-specific layer. Generic CLI knowledge lives in:

- `unity-cli` (`.claude/skills/unity-cli/`): every `unity` command, global flags, exit codes, JSON envelopes. Read its `references/*.md` for the command group you need.
- `unity-pipeline` (`.claude/skills/unity-pipeline/`): the Editor-control loop (`set_autotick`, `recompile`, `run_tests`, `run_script`, `reload_file`).

Both are generated by `unity skill install claude-code --local`. Do not hand-edit them; see [Maintenance](#maintenance).

**Use the CLI, not MCP.** This agent has a shell, and `unity command` is faster and costs fewer tokens than an MCP round trip. Only fall back to the `unity-mcp-skill` / MCP tools if the CLI is unavailable.

The machine often runs **several Editors at once**: for example, `ApexionGames-PagePilot` is also on `6000.3.20f1`. The CLI picks a target from the current directory, so a call without `--project-path` can reach the wrong project or fail with `AMBIGUOUS_EDITOR`. **Never send commands to another project's Editor.**

## Rule 1: go through the wrapper

```bash
S=.claude/skills/grass-unity-editor/scripts/ucmd.sh   # relative to project root
bash $S editor_status --result-only
bash $S console --tail 20 --level error --result-only
```

`ucmd.sh` always adds `--project-path <this project>`, `--format json`, and turns off the pager, banner and prompts. If you call `unity command` directly, pass `--project-path "D:\KCGames-Studio\KCGames-GrassSimulation"` yourself.

**Flag order matters.** CLI options (`--timeout`, `--detach`, `--project-path`, `--format`) belong before the command name or are recognised CLI flags. Any unknown `--flag` after the command name is forwarded to the Editor command and fails with `INVALID_COMMAND_ARGS ... has no parameter --x` (exit 2). `--result-only` works in either position.

## Rule 2: run Unity CLI through the Bash tool, not PowerShell

Windows PowerShell 5.1 mangles embedded `"` in arguments to native executables. For example, `eval 'return a + " | " + b;'` gets split into extra positionals and fails with exit 2. In Git Bash, single-quoted C# works as written:

```bash
bash $S eval 'return UnityEditor.SceneManagement.EditorSceneManager.GetActiveScene().path;' --result-only
```

- `eval` is for one-liners only. Anything longer than one statement goes in a file run by `run_script` (below).
- Use fully qualified type names in `eval` (`UnityEngine.GameObject`), because no `using` directives apply.

## Rule 3: preflight before touching scenes, assets or code

```bash
bash $S editor_status --result-only
```

| Result | Action |
|---|---|
| `status: "ready"` | Proceed. |
| `compiling: true` / `domainReloadInProgress: true` | Wait (`bash $S recompile_status`) and retry. Connection errors during a domain reload are expected. |
| `status: "blocked_by_dialog"` | A modal dialog is open. Stop, report `dialog.title`/`message`/`buttons` to the user, and wait. The CLI cannot click it. |
| exit 7 / no instance | Run `unity status --json`. If this project is missing, run `unity pipeline list` from the project root to check for **Safe Mode** (compile errors). If it is not Safe Mode, ask the user whether the Editor is open. The sandbox may be hiding it. Do not silently fall back to file edits. |

Before long or unfocused work (recompiles, tests, Play Mode), run this once per Editor session:

```bash
bash $S set_autotick --enable true
```

## Core loops

### C# change → compile → test

```bash
# 1. edit .cs files on disk
bash $S recompile                         # async: triggers domain reload
bash $S recompile_status --result-only    # poll until status completed|up_to_date; read errors[] if failed=true
bash $S console --tail 30 --level error --result-only
bash $S list_tests --mode editor --result-only
bash $S run_tests --mode editor --filter <Fixture.Test> --result-only   # filter_type: testName|assembly|category
```

`unity recompile --project-path <root> --json` is a one-shot alternative that waits and reports compile errors. Exit 7 there means the Editor is unreachable, so check for Safe Mode.

### Scene / GameObject / component work

Discover before you act, because command names and parameters come from the Editor:

```bash
bash $S --tags                                    # 48 tags: gameobjects, scenes, prefabs, assets, settings/*, baking/*, ...
bash $S --tag gameobjects --detail compact        # commands under one tag
unity command --query set_component_properties --detail full --project-path "D:\KCGames-Studio\KCGames-GrassSimulation"   # params of one command
unity list --project-path "D:\KCGames-Studio\KCGames-GrassSimulation" --json  # full JSON schema of every tool (~140 KB, so grep it)
```

Typical flow: `list_open_scenes` → `get_scene_hierarchy` → `find_gameobjects --name ...` → `get_component_properties` → `set_component_properties` / `set_serialized_field` → **`save_scene`**. Changes in the Editor are not on disk until saved.

**Never hand-edit `.unity`, `.prefab`, `.asset` or `.meta` YAML while the Editor is reachable.** Hand edits break fileIDs and GUIDs and are invisible to the running Editor.

### Bulk construction: `run_script`

Put builder code **outside `Assets/`** so writing it does not trigger an import or domain reload:

```bash
# AgentScripts/Build.cs:  public static class Build { public static object All() { ...; return summary; } }
bash $S run_script --file AgentScripts/Build.cs --dry_run true             # compile-only check
bash $S run_script --file AgentScripts/Build.cs --entry Build.All --result-only
bash $S run_script --file AgentScripts/Build.cs --entry Build.All --args '[3, "Green"]'
```

Return a summary object so you can verify the result, and then inspect it with `get_scene_hierarchy` / `capture_scene_view`.

### Play Mode verification

Before claiming that gameplay or the grass simulation "works", follow `unity-cli/references/playmode-verification-loop.md`. An unfocused Editor can freeze at frame 1 while it still reports `playing`. In short: `editor_play` → `unity status --json` (check `frameCount` advances and `playerLoopTicking`) → `capture_game_view` → `console --level error` → `editor_stop`.

### Burst / Jobs notes

- Game code uses Burst and the Job System but **not ECS** (`docs/conventions/CODING-CONVENTIONS.md` Section 13.2). Do not add Entities, subscenes or bakers to game code.
- Burst compiles asynchronously in the Editor. After a recompile, check `console --level error` and `--level warning` for Burst diagnostics before trusting Play Mode results.
- To measure a job-heavy change, use `get_performance_stats` in Play Mode before and after the change, and report both numbers.

## Confirmation policy

Ask the user before running any of these:

- **Destructive or irreversible:** `delete_asset`, `delete_gameobject` (on saved scenes), `move_asset`/`rename_asset` on shared assets, `package_remove`, `clear_baked_lighting`, `clear_navmesh`, `revert_prefab_overrides`, `unpack_prefab`.
- **Expensive or disruptive:** `switch_build_target`, `bake_lighting`, `bake_navmesh*`, `bake_occlusion_culling`, `build`, `quit`, `package_add`, any `set_*_settings` (Player, Quality, Graphics, Physics, Time, Input, Tags/Layers).
- **CLI-level:** `unity pipeline upgrade`, `unity self-update`, `unity install*`, `unity uninstall`, `unity close`, and any `vcs` command that writes.

These are safe to run without asking: reads (`get_*`, `find_*`, `list_*`, `console`, `editor_status`, `capture_*`, `search`), `recompile`, `run_tests`, `eval` with no side effects, and edits the user explicitly requested followed by `save_scene`.

## Reading results

- Branch on `success` and the exit code, never on stderr. `errors[0].code` is the stable token to branch on.
- Exit codes: `2` = your invocation is wrong (fix it; do not retry unchanged). `6` = the Editor ran it and it failed (read the error; do not retry blindly). `7` = Editor unreachable (preflight again). `8` = `unity test` ran and tests failed (do not retry).
- If a JSON envelope carries `notifications` (for example `CLI_UPDATE_AVAILABLE`), tell the user. Do not run `remediation.command` when `requiresUserApproval` is true.

```bash

```
